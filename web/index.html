Qui · En quelques lignes

Le grain avant l’abstraction

Je m’appelle Zacharie L. Nolet. J’étudie en Techniques de l’informatique au Cégep de Victoriaville et je construis des logiciels avec une règle simple : le grain avant l’abstraction. Un écran ne calcule pas un rang. Une règle métier vit dans une fonction pure, avec son test, avant de vivre dans un thème.

Mon projet de référence est un cahier de lecture iPhone : dix textes par jour, un classeur hors-ligne, une synchronisation par file d’opérations idempotentes, un backend PHP minimal. Pas de fil infini, pas de « j’aime ».

Côté décision, je m’intéresse aux systèmes de gestion tels qu’ils tournent en entreprise : Sage X3 est l’opérationnel, Nectari clone le champ certifié, Jitterbit cadence l’intégration, Power BI lit le mart. Je n’invente pas un KPI ; je refuse de sommer un ratio.

En 2026, mon équipe a reçu le prix « Badge fort, salue l’effort » à l’Exposat, en Techniques de l’informatique. Le parcours complet.

Le code affiché est le code qui tourne

Sur la page Preuves, chaque source est lue au chargement par le navigateur : c’est la fonction réelle qui s’exécute à côté. Modifie les entrées, regarde le résultat.

    Normalisation Unicode, portée du TypeScript du dépôt.

  2. Édition déterministe

    Hachage FNV-1a : même date, même résultat sur tout appareil.

  3. File idempotente et fusion last-write-wins

    Synchronisation hors-ligne sans doublon ni écrasement.

  4. Un ratio ne se somme pas

    La mesure Power BI juste, avec l’écart sous les yeux.

  5. Règles CPQ avant l’écran

    Exigences, exclusions, remise : un prix déduit, jamais saisi.

    La mémoire n’appartient pas à un format propriétaire.
